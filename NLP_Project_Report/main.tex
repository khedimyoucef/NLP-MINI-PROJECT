\section{Introduction and Problem Statement}
\label{sec:intro}

\subsection{The Challenge: Domain-Specific Text Generation}
Large Language Models (LLMs) are incredibly capable zero-shot generalists. However, when tasked with creating highly specific content—such as educational stories tailored to exact age groups—they often drift into generic language, hallucinate complex vocabulary, or fail to adhere to structural constraints.

Two primary challenges define this project:
\begin{itemize}[noitemsep, topsep=0pt]
    \item \textbf{Style Adaptation:} Adjusting the model's tone to be engaging, safe, and comprehensible for young children, categorized strictly by age levels.
    \item \textbf{Resource Constraints:} Fine-tuning billions of parameters requires substantial compute memory. Developing a pipeline capable of running on accessible hardware (like Kaggle's dual T4 GPUs) is critical.
\end{itemize}

\subsection{Our Approach: Multi-Model Fine-Tuning and Edge Deployment}
We fine-tuned Google's \texttt{gemma-4-E2B-it} and \texttt{gpt2-small} models on a curated children's story dataset. To bypass hardware limitations for the larger Gemma model, we utilized 4-bit Quantized Low-Rank Adaptation (QLoRA). Once trained, the adapters were merged back into the base model and converted into a highly optimized \texttt{.gguf} format, enabling fast, local inference on edge devices via \texttt{llama.cpp}. For comparison, we also included two base models: \texttt{gpt2-xl} and \texttt{gemma-4-E4B-it}.

\section{Background: Parameter-Efficient Fine-Tuning}
\label{sec:background}

\subsection{The Memory Bottleneck}
Training an LLM requires memory for model weights, gradients, optimizer states, and activations. A 2-billion parameter model in 16-bit precision requires roughly 4GB just to hold the weights, but over 16GB to train fully. This makes full fine-tuning inaccessible for consumer GPUs.

\subsection{Quantization and QLoRA}
To solve this, we employ \textbf{QLoRA} for the Gemma model. The base model is loaded in 4-bit precision (NF4), drastically reducing the memory footprint. Instead of updating the original weights, QLoRA injects small, trainable "adapter" matrices into the model's layers. During training, only these adapter weights are updated while the base model remains frozen.

\centering

\caption{LoRA architecture: small rank decomposition matrices are trained while the pre-trained weights remain frozen.}
\label{fig:lora}
\end{figure}

\section{Model Architectures and Selection}
\label{sec:model}

For this project, we employed a mix of fine-tuned and base models to thoroughly evaluate the impact of domain adaptation against out-of-the-box generalization.

\subsection{Gemma 4 E2B-IT (Fine-Tuned)}
We selected the \texttt{gemma-4-E2B-it} (Instruction Tuned) variant, featuring roughly 2.3 billion effective parameters. Released as part of the Gemma 4 family, this model incorporates several advanced architectural innovations that make it particularly suited for our edge-deployment and domain adaptation goals:

\begin{itemize}[noitemsep, topsep=0pt]
    \item \textbf{Per-Layer Embeddings (PLE):} The "E" in E2B stands for "Effective" parameters. Instead of a single large input embedding table, PLE feeds a secondary embedding signal into every decoder layer. This provides the representational depth of a larger model while keeping the actual active parameter count and memory footprint low.
    \item \textbf{Alternating Attention \& Shared KV Cache:} The architecture alternates between local sliding-window attention and global full-context attention. Combined with a shared Key-Value (KV) cache in the final layers, this drastically reduces memory consumption during inference and allows for a massive context window of up to 128K tokens.
    \item \textbf{Dense \& Multimodal Native:} Unlike the larger Mixture-of-Experts (MoE) variants in the Gemma 4 family, E2B is a dense transformer. While natively multimodal (supporting text, image, and audio), our project strictly utilizes its robust text-processing capabilities via its massive 256,000-token vocabulary.
    \item \textbf{Edge-Optimization:} Designed specifically to minimize VRAM usage and latency, it fits comfortably on a single 16GB GPU for QLoRA fine-tuning and can be quantized to run entirely on consumer CPU RAM.
\end{itemize}
\begin{figure}[htbp]
\centering
\includegraphics[width=0.8\textwidth]{pics/gemma4famillySpecs.png}
\caption{a bit of details about the gemma 4 family for more details visit : \url{https://huggingface.co/google/gemma-4-E2B-it}}
\label{fig:gemma4famillySpecs}

\subsection{GPT-2 Small (Fine-Tuned)}
As a lightweight alternative to Gemma, we fully fine-tuned \texttt{gpt2-small} (124M parameters). Being much smaller, it allowed us to experiment with full fine-tuning without the need for QLoRA. It serves as our baseline for domain-adapted text generation with limited capacity.

\subsection{Base Models for Comparison}
To contrast our fine-tuned models with zero-shot generalists, we included two base models in our evaluation pipeline:
\begin{itemize}[noitemsep, topsep=0pt]
    \item \textbf{GPT-2 XL (1.5B parameters):} A larger version of GPT-2 to observe how scaling parameters compensates for lack of domain-specific fine-tuning.
    \item \textbf{Gemma 4 E4B-IT (\textasciitilde 4B parameters):} A significantly larger variant of the Gemma family. We quantized it to GGUF format to run locally and use it as a high-end baseline.
\end{itemize}

\section{Dataset}
\label{sec:dataset}

\subsection{Source and Formatting}
We utilized the \texttt{ajibawa-2023/Children-Stories-Collection} dataset from Hugging Face. The dataset consists of story prompts and corresponding stories suitable for children. 

To teach the model to adapt its vocabulary, we prefixed each prompt with an age-level constraint. The training samples were formatted into Gemma's native instruction format:

\begin{lstlisting}[language=json, breaklines=true, basicstyle=\small\ttfamily]

<start_of_turn>model

\section{Training Methodology}
\label{sec:training}

\subsection{Configuration and Hardware}
Training was orchestrated using the Hugging Face \texttt{Trainer} API on a Kaggle environment equipped with dual NVIDIA T4 GPUs. 

Key training parameters for Gemma:
\begin{pythoncode}[Training Arguments]
training_args = TrainingArguments(
    per_device_train_batch_size=1,
    gradient_accumulation_steps=16,
    optim='paged_adamw_8bit',
    learning_rate=2e-4,
    fp16=True,
    gradient_checkpointing=True,
    eval_strategy='no' # Disabled to prevent OOM
)
\end{pythoncode}

\subsection{Overcoming Memory Constraints}
Due to Gemma 4's massive 256K token vocabulary, calculating cross-entropy loss over large sequences creates a massive memory spike. We mitigated this by:
\begin{enumerate}
    \item Enforcing \texttt{batch\_size = 1} with high gradient accumulation (16 steps) to simulate a batch size of 16.
    \item Enabling \texttt{gradient\_checkpointing} to trade computation time for VRAM savings.
    \item Setting \texttt{PYTORCH\_CUDA\_ALLOC\_CONF=expandable\_segments:True} to prevent CUDA memory fragmentation.
\end{enumerate}

\section{Model Export and Deployment}
\label{sec:export}

\subsection{Merging the Adapters and Quantization}
For the Gemma model, QLoRA results in standalone adapter weights. We reloaded the base model in FP16 precision on the CPU, injected the LoRA weights, and invoked \texttt{merge\_and\_unload()} to fuse them permanently.

To deploy the model locally, we converted the merged model into the GGUF standard using \texttt{llama.cpp}. The FP16 model was further quantized down to \texttt{Q4\_K\_M} (4-bit, medium quantization). This reduced the model's disk footprint to approximately 1.5 GB, allowing it to run entirely on consumer CPU RAM.

Another problem we faced was the management of Kaggle's limited RAM and storage resources, so we had to implement a pipeline that constantly monitored and cleaned up unnecessary files after each stage.

\section{Discussion and Limitations}

While the fine-tuned models successfully generated formatted, age-appropriate children's stories, several challenges and limitations remain:
\begin{itemize}[noitemsep, topsep=0pt]
    \item \textbf{Vocabulary Size Overhead:} The 256k vocabulary size of Gemma 4 makes cross-entropy loss computation extremely expensive in VRAM, restricting training batch sizes and evaluation strategies.
    \item \textbf{Catastrophic Forgetting:} By fine-tuning purely on children's stories, the model's general instructional capability may degrade outside of this specific domain.
    \item \textbf{Hallucinations:} Without grounding constraints, the model may occasionally generate nonsensical plot resolutions. Future work could involve RAG (Retrieval-Augmented Generation) to ground the stories in specific educational facts.
\end{itemize}

\section{Local Reproduction Guide}
\label{sec:reproduction}

To fully reproduce this project locally (e.g., on a personal CPU without GPU acceleration), follow these steps. \textbf{Note:} Downloading all models can require significant storage space. The web app has been designed to start gracefully and make all models optional; you only need to download the ones you wish to test.

\subsection{1. Environment Setup}
Ensure you have an environment manager like \texttt{micromamba} or \texttt{conda} installed.

\begin{pythoncode}[Install Dependencies]
micromamba create -n NLP python=3.10
micromamba activate NLP
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
\end{pythoncode}

\subsection{2. Download the Models (Optional)}
You can download specific models you want to try. Run the \texttt{download\_model.sh} script and specify the Hugging Face repository and local directory.

\textbf{Example: Downloading Fine-Tuned GPT-2 Small}
\begin{pythoncode}[Download GPT-2 Small]
export REPO_ID="khedim/NLP-MINI-PROJECT"
export MODEL_DIR="models/story-gpt2"
bash scripts/download_model.sh
\end{pythoncode}

\textbf{Example: Downloading Fine-Tuned Gemma (GGUF)}
\begin{pythoncode}[Download Gemma E2B]
export REPO_ID="khedim/NLP-MINI-PROJECT"
export MODEL_DIR="models/gemma-4-E2B-it-finetuned"
bash scripts/download_model.sh
\end{pythoncode}

\textbf{Example: Downloading Base GPT-2 XL}
\begin{pythoncode}[Download GPT-2 XL]
export REPO_ID="openai-community/gpt2-xl"
export MODEL_DIR="models/gpt2-xl"
bash scripts/download_model.sh
\end{pythoncode}

\textbf{Example: Downloading Base Gemma 4 E4B-IT (GGUF)}
\begin{pythoncode}[Download Gemma E4B]
export REPO_ID="khedim/NLP-MINI-PROJECT"
export MODEL_DIR="models/gemma-4-E4B-it-gguf"
bash scripts/download_model.sh
\end{pythoncode}

\subsection{3. Run the API and Web UI}
Start the local server using the provided script.

\begin{pythoncode}[Run Local Server]
bash scripts/run_api.sh
\end{pythoncode}

Once started, open \url{http://localhost:8000/} in your web browser. The app will automatically detect any models present in the \texttt{models/} directory and make them available in the dropdown menu. If you only downloaded one model, the app will safely load it without crashing.
